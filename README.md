# SanaBrief · AI Sana

Hackathon team repository for DT20 — Aldiyar, Abylaikhan, Zhadiger.

**MVP полного сценария AI Sana: черновик → вопросы → карточка → рейтинг → каталог → отклик → выбор бизнеса → подтверждённый этап и XP.**

Интерфейсы бизнеса, каталога, публичной карточки и команды объединены с серверными API. На настроенном окружении разработчика прошли реальные AI-запросы, загрузка в Supabase и сквозной HTTP-сценарий. Отдельный публичный стенд пока не проверен.

## Запуск

Нужен Node.js 22.15+ (рекомендуется актуальная LTS-версия). Из папки репозитория:

```bash
npm ci
npm run dev
```

Откройте [127.0.0.1:3000](http://127.0.0.1:3000). Для самостоятельной демонстрации установите `NEXT_PUBLIC_DATA_MODE=local`; в каталоге нажмите «Добавить демопримеры» или «Создать задачу». Используйте один и тот же адрес: браузер хранит данные localhost и 127.0.0.1 отдельно.

## Что реализовано

- Три шага: свободное описание → 5 уточняющих вопросов → редактируемая карточка.
- Все поля ТЗ: контекст, потребность, пользователи, данные, ограничения, результат, критерии успеха, контакт и взаимодействие.
- Рейтинг 0–100, семь составляющих, четыре уровня и подсказки с переходом к нужному полю.
- Автосохранение, список «Мои задачи» и восстановление по адресу `/tasks/[id]/edit`.
- Предпросмотр, ручное подтверждение и отдельное действие публикации.
- Разделение черновика и подтверждённой версии: новые правки не меняют опубликованные сведения до подтверждения.
- Публикация допускается при любом рейтинге, включая 0. Название и ручное подтверждение обязательны.
- Обработка сетевых ошибок, таймаута, некорректных ответов и недоступного браузерного хранилища.
- Переключаемый HTTP-адаптер для сервера участника №2, без API-ключей в браузере.
- Русскоязычный интерфейс, адаптивная вёрстка, доступные подписи, управление с клавиатуры и диалоги Radix.
- Каталог `/catalog`: поиск, фильтры по теме и уровню, сортировка по подтверждённому рейтингу. Все опубликованные задачи доступны, включая 0–39.
- Полная публичная карточка `/tasks/[id]` и форма отклика с выбором демокоманды, идеей, планом, сроком и ссылкой на прототип.
- Кабинет бизнеса `/business`: собственные задачи, сравнение предложений, ручной выбор нескольких команд или отклонение всех, подтверждение результата этапа.
- Кабинет команды `/student`: профиль, навыки, технологии, статусы откликов, отправка результата и XP.
- +10 XP за подтверждённый бизнесом этап; повторное подтверждение не начисляет баллы снова. Подтверждённый результат нельзя подменить.
- Синтетический набор: 5 черновиков, 5 опубликованных карточек четырёх уровней, 5 команд и 5 откликов. Повторное добавление сохраняет пользовательские правки.
- Общие шапка, подвал и навигация всех страниц; логотип ведёт в каталог, переходы из редактора дожидаются сохранения.
- Собственные отклики и отправка результата доступны также прямо в публичной карточке задачи.
- Совместимость с сохранёнными откликами участника №3: старый массив читается без потери статусов, результатов и XP; следующий успешный запрос сохранения переводит его в общий формат.

Для автоматического показа исторического набора участника №3 задайте `NEXT_PUBLIC_COLLAB_FIXTURES=1` в локальном режиме. По умолчанию флаг выключен, используется новый набор через кнопку «Добавить демопримеры». Существующие записи не перезаписываются; если у двух наборов совпадает ID, отклик-пример не добавляется к задаче с другим содержанием. В `/business` доступен локальный сброс примеров с явным подтверждением. Он восстанавливает только известные примеры, сохраняет созданные пользователем задачи и отклики и предварительно записывает резервную копию обоих хранилищ в `sana-brief.demo-backup.v1` (поля `tasks` и `proposals` содержат прежние строки хранилищ).

**Локальный режим полностью воспроизводит сценарий в одном браузере.** Вопросы выбираются по шаблонам, карточка переносит введённые сведения, задачи и отклики хранятся в `localStorage`. Настоящий AI не вызывается; между устройствами эти данные не синхронизируются. Переключайтесь между кабинетами через верхнюю навигацию. Ссылки example.com и контакты демонабора синтетические.

В API-режиме те же экраны работают через серверные обработчики и Supabase. Это общий демостенд: страницы и API доступны сразу, без регистрации, логина и пароля. AI допускает прозрачный резервный режим согласно ТЗ.

После сброса в кабинете бизнеса появляется «Отменить последний сброс»: восстанавливаются прежние демопримеры, их результаты и XP; пользовательские записи сохраняются.

## Стек

Next.js App Router, React, TypeScript, Tailwind CSS, Radix Dialog, Lucide, Zod, Vitest. Версии зафиксированы в `package-lock.json`. Стили и компоненты находятся в репозитории; загрузка внешних шрифтов или изображений не нужна.

## Подключение сервера

Для API-режима задайте `NEXT_PUBLIC_DATA_MODE=api`, настройте серверные переменные и Supabase по [docs/BACKEND.md](docs/BACKEND.md), затем перезапустите приложение. `NEXT_PUBLIC_API_BASE_URL` оставьте пустым для API этого Next.js-проекта. Примените `supabase/schema.sql`, затем нажмите «Добавить демопримеры»: задачи и отклики добавляются без перезаписи существующих записей. Контракт описан в [docs/INTEGRATION.md](docs/INTEGRATION.md).

По просьбе владельца для временной работы команды на приватном хакатонном репозитории `.env.local` отслеживается Git. Не переносите его содержимое в публичный репозиторий или клиентский код. Серверные ключи не должны иметь префикс `NEXT_PUBLIC_`.

AI-ключи и ключи базы используются только сервером. В API-режиме нет скрытого перехода к локальному сохранению при ошибке: интерфейс сообщает о сбое. Шаблонное уточнение можно выбрать явно, если AI-обработчик недоступен, но серверное сохранение продолжает требовать работающий API.

## Формула рейтинга

| Группа                 | Баллы | Подпункты                                            |
| ---------------------- | ----: | ---------------------------------------------------- |
| Контекст и потребность |    20 | Контекст 10 + потребность 10                         |
| Данные и материалы     |    20 | Описание 10 + источник/доступ 10                     |
| Ожидаемый результат    |    15 | Конкретный результат 15                              |
| Критерии успеха        |    15 | Показатель 10 + условие приёмки 5                    |
| Ограничения            |    10 | Срок 5 + границы работы 5                            |
| Пользователи           |    10 | Пользователи 10                                      |
| Связь с бизнесом       |    10 | Контакт 5 + формат консультаций 3 + обратная связь 2 |

Уровни: 0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Пустые значения и распространённые заглушки не дают баллов; для контакта проверяется формат. Базовая оценка проверяет заполненность; AI-проверка дополнительно оценивает смысл и конкретность 13 полей, а сервер начисляет баллы по фиксированным весам.

В редакторе отображается предварительная оценка и объяснения проверки качества. Правки делают прежнюю проверку недействительной. Подтверждённые баллы закрепляются только после ручного подтверждения; сервер проверяет точное текущее содержимое и сам пересчитывает официальный рейтинг по фиксированным весам для принятых полей. Детерминированная резервная проверка явно помечается `fallback`. `publishedAt` определяет публикацию независимо от уровня.

## Проверки

Значок рядом с «Готовность задачи» открывает русскую справку с формулой рейтинга.

В режиме разработки слева снизу доступен штатный индикатор N с панелью Next.js. Это инструмент разработчика; его меню отображается на английском.

```bash
npm run typecheck
npm test
npm run build
```

Тесты проверяют границы уровней, пустые поля, формат контактов, сценарий 35 → 80 → 100, подтверждение человеком, публикацию слабой задачи, независимость черновика от опубликованной версии, восстановление данных, ошибки хранилища и проверку AI-ответов.

Дополнительно проверяются конфликт двух вкладок, защита подтверждения/публикации от устаревшей версии, уникальность версии быстрых записей, отмена ввода во время медленного сохранения и повторное использование ID вопросов. При конфликте UI позволяет сохранить правки отдельной копией. Локальная запись требует Web Locks (HTTPS или localhost); требования к серверной защите описаны в `docs/INTEGRATION.md`.

Для production-запуска после сборки: `npm start`.

## Ручная проверка части №1

1. Откройте `/tasks/new`, заполните описание или выберите пример пекарни.
2. Получите 5 вопросов. Ответьте минимум на часть; пустые ответы допустимы.
3. Соберите карточку. Проверьте, что отсутствующие сведения остались пустыми.
4. Заполните название; измените поля и убедитесь, что рейтинг пересчитывается.
5. Откройте предпросмотр. Закройте его клавишей Escape.
6. Отметьте подтверждение достоверности и нажмите «Подтвердить карточку».
7. Нажмите «Опубликовать задачу». В локальном режиме увидите сообщение о демопубликации.
8. Измените поле: появятся предварительный рейтинг и отметка «Есть правки». Предпросмотр опубликованной версии содержит старые сведения.
9. Подтвердите изменения: опубликованная карточка обновится.
10. Перезагрузите страницу: сведения сохранятся. Через «Мои задачи» можно открыть другую карточку.
11. Отдельно опубликуйте неполную задачу с низким рейтингом.

# Сервер участника 2

Серверные обработчики Supabase и AI объединены с интерфейсом. Проверки без ключей используют локальное хранилище и тестовый репозиторий; живые Supabase/OpenAI проверяются отдельно после настройки окружения.
Настройка и проверки: [docs/BACKEND.md](docs/BACKEND.md).
Контракт для участника 3: [docs/HANDOFF-PARTICIPANT-3.md](docs/HANDOFF-PARTICIPANT-3.md).
Версионные запросы редактора: [docs/INTEGRATION.md](docs/INTEGRATION.md).

Для общего демостенда предусмотрены `npm run seed:demo` (пять черновиков, пять опубликованных карточек, пять команд и пять откликов), `npm run smoke:backend` (сценарий HTTP) и `npm run check:ai -- --expect=ai` либо `--expect=fallback` (проверка источника AI-ответа). Загрузка демоданных использует детерминированные идентификаторы и не перезаписывает существующие записи. Запускайте проверки после настройки окружения по `docs/BACKEND.md`; результаты для конкретного стенда фиксируйте отдельно.
