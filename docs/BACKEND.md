# Сервер участника 2

## Запуск

1. `npm.cmd ci`.
2. Настроить `.env.local` по переменным из `.env.example`. По просьбе владельца файл временно отслеживается в приватном хакатонном репозитории для общей среды команды; его содержимое нельзя переносить в публичный репозиторий или клиентский код.
3. Выполнить `supabase/schema.sql` в SQL Editor отдельного тестового проекта.
4. Установить `NEXT_PUBLIC_DATA_MODE=api`, `AI_MODE=live`, `OPENAI_MODEL` в доступную модель с Structured Outputs.
5. `npm.cmd run dev`. Открыть `/tasks/new`.

Все маршруты реализованы в `src/app/api/[...path]/route.ts`. Логика состояния — `src/lib/task-service.ts` (server/service.ts экспортирует её для совместимости), адаптер Supabase — `server/database.ts`. Локальный режим использует те же бизнес-правила с браузерным адаптером. Ключи и SDK остаются в server/database.ts и server/model.ts, клиент их не импортирует.

## Cloudflare Tunnel

В `.env.local` задать `APP_ORIGIN=https://ваш-домен.trycloudflare.com` без `/tasks/new`. Оставить `NEXT_PUBLIC_API_BASE_URL` пустым: браузер отправляет запросы через тот же туннель. `NEXT_PUBLIC_DATA_MODE=api` включает серверное сохранение.

Перезапустить `npm.cmd run dev`, направить туннель на `http://127.0.0.1:3000`, затем открыть внешний адрес. Если адрес Quick Tunnel изменился, обновить `APP_ORIGIN` и снова перезапустить сервер. Этот адрес разрешается для служебных ресурсов Next.js и записи в API за HTTPS-прокси. Произвольные домены и заголовки `X-Forwarded-*` не используются для разрешения записи.

Доступ по туннелю открыт без логина и пароля и использует тот же общий демонстрационный профиль.

## Доступ и ограничения деморежима

Это общий демонстрационный бизнес-профиль: владельца задаёт сервер через `DEMO_OWNER_ID` (по умолчанию `demo-business`), а не браузер. Все посетители демостенда могут разыгрывать обе роли, выбирать демокоманду и выполнять действия бизнеса. Регистрации и индивидуальной авторизации нет.

Страницы и API доступны без учётных данных во всех режимах, включая production. HTTP Basic удалён, браузер не получает запрос логина и пароля. Старая переменная `DEMO_ACCESS_PASSWORD`, если осталась в окружении сервера, игнорируется. `/api/health` проверяет работу приложения без входа. Сервер локальной разработки по умолчанию запускается на loopback.

Перед полноценным публичным использованием нужны пользовательские сессии и права по ролям. Ограничитель AI допускает 10 запросов в минуту на процесс; он подходит для одного демонстрационного сервера, но не заменяет общий лимит для нескольких экземпляров.

## Реализованные операции

| Метод | URL | Результат |
|---|---|---|
| GET | `/api/health` | Проверка приложения, не проверка базы |
| POST | `/api/ai/questions` | `{questions, source}` |
| POST | `/api/ai/card` | `{content, source, evidence?}` |
| POST | `/api/ai/quality` | QualityReview; `{content,industry}` |
| POST | `/api/tasks` | Task; id от клиента, повтор создания не перезаписывает данные |
| GET | `/api/tasks/:id` | Полный Task текущего бизнеса |
| PATCH | `/api/tasks/:id/draft` | Сохранённый Task |
| POST | `/api/tasks/:id/confirm` | Подтверждённый Task, `{acknowledged:true,expectedRevision}` |
| POST | `/api/tasks/:id/review` | Task с проверкой качества, `{expectedRevision}` |
| POST | `/api/tasks/:id/publish` | Опубликованный Task, `{expectedRevision}` |
| GET | `/api/tasks?industry=…&level=…` | PublishedTask[] |
| GET | `/api/catalog/:id` | PublishedTask без черновика и ответов |
| GET | `/api/business/tasks` | Task[] текущего бизнеса |
| GET | `/api/teams` | Team[] с вычисленным xp |
| GET | `/api/student/proposals?teamId=…` | Proposal[] выбранной демокоманды |
| POST | `/api/demo/seed` | `{acknowledged:true}` → `{ok:true}`; добавить синтетический набор |
| POST | `/api/tasks/:id/proposals` | Proposal |
| GET | `/api/business/proposals?taskId=…` | Proposal[] текущего бизнеса |
| PATCH | `/api/proposals/:id` | Proposal; тело `{status:"accepted"}` или rejected |
| PATCH | `/api/proposals/:id/result` | Proposal; `{resultDescription,resultUrl}` |
| POST | `/api/proposals/:id/confirm-stage` | Proposal; `{acknowledged:true}` |

Подробные поля форм — в `HANDOFF-PARTICIPANT-3.md`. Все успешные запросы возвращают JSON с HTTP 200. Ошибки: `{error,code}`. Запись требует `Content-Type: application/json`, максимальный размер тела 64 KiB. Межсайтовые запросы записи запрещены.

Supabase хранит три таблицы. tasks содержит owner_id, полный Task в payload и revision; proposals — task_id, team_id, полный Proposal и revision; teams — профили. revision используется для условного обновления: конкурентная запись возвращает 409 вместо потери изменений. После подтверждения этапа его результат и статус нельзя менять; XP вычисляется из подтверждённых этапов, а не накапливается повторными инкрементами.

Браузерные роли не имеют доступа к таблицам. Включён RLS, доступ через SDK выполняется серверным ключом. SQL не удаляет существующие данные и добавляет пять синтетических команд. Кнопка «Добавить демопримеры» вызывает защищённый теми же правилами `/api/demo/seed` и добавляет 5 черновиков, 5 опубликованных карточек всех уровней и 5 откликов из `src/lib/demo-data.ts`. Команда `npm.cmd run seed:demo` загружает тот же набор через API. Фиксированные UUID и вставка без перезаписи сохраняют правки при повторных запросах; операцию можно повторить после частичного сбоя. При отсутствии демокоманд сервер сообщает о необходимости применить `supabase/schema.sql`. Для скриптов нужен Node.js 22.15+.

## AI

Для сохранения черновика также требуется `expectedRevision` из последнего ответа Task. Сервер сверяет клиентскую версию с сохранённой и возвращает 409 при устаревших данных. Gateway и очередь редактора обновляют revision после успешных операций. Это защищает и от пересекающихся запросов, и от сохранения старого снимка из второй вкладки.

Используется Responses API, Structured Outputs, `store:false`. Таймаут одной попытки 18 секунд, максимум две попытки, затем явно обозначенный `source:fallback`; клиент ждёт до 45 секунд. При AI_MODE=mock, отсутствии ключа или модели возвращается резервный результат. Он не маскирует ошибки базы. Диагностика пишет только категорию сбоя, тип операции и время, без ключей, входного текста и ответа модели.

Для заполненных AI-полей проверяются цитаты-основания из пользовательского ввода: значение поля должно быть непрерывным фрагментом цитаты, сама цитата — фрагментом исходных сведений; допускается нормализация пробелов. Наличие настоящей цитаты рядом с выдуманным значением недостаточно. Неизвестные значения остаются пустыми. Пользователь по-прежнему проверяет правильность отнесения цитаты к полю и подтверждает карточку.

### Проверка рейтинга

Специальный русскоязычный промпт `QUALITY_PROMPT` находится в `src/lib/server/prompts.ts`. Модель возвращает 13 решений accepted/reason/suggestion: конкретность процесса, потребности, пользователей, данных, результата, приёмки, сроков и взаимодействия. Запросы повысить рейтинг внутри описания считаются данными и не меняют критерии. ИИ не назначает число баллов; фиксированные веса применяет `calculateReviewedScore` на сервере. Пустые поля, заглушки и мусор не получают баллов даже при ошибочном одобрении моделью. Корректный числовой телефон и числовая цель вместе с описанной метрикой допустимы.

Кнопка «Проверить качество с ИИ» сохраняет `qualityReview` для точного сочетания content/industry. Редактирование сбрасывает проверку; сервер не принимает её от клиента. Повторная явная проверка позволяет повторить запрос после временного fallback. Подтверждение использует актуальную проверку или получает новую, после чего атомарно сохраняет официальный рейтинг. Новый предварительный рейтинг не меняет каталог до подтверждения. Проверка не запускается при наборе текста. `inputKey` — внутренний идентификатор содержимого, его нельзя выводить в логи или интерфейс.

Резервный режим выполняет базовые проверки заполнения, формата и повторов, но не обещает смысловую точность AI. Низкий балл не запрещает публикацию и отклики.

## Проверки

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
```

На запущенном приложении с настроенной базой:

```powershell
node scripts/smoke-backend.mjs
```

Скрипт создаёт временную задачу и три отклика, проверяет нулевой рейтинг, версии, сброс проверки после правок, изоляцию подтверждённой карточки, принятие двух команд, отклонение и однократное начисление XP. В finally удаляет только свои записи по случайному UUID. В AI_MODE=live подтверждение и проверка задачи могут вызывать модель; использованы только синтетические сведения.

`npm.cmd run check:ai -- --expect=ai` проверяет настоящий ответ модели для вопросов, карточки и качества. Для сервера с AI_MODE=mock: `npm.cmd run check:ai -- --expect=fallback`. Другой адрес сервера задаётся через CHECK_BASE_URL; для smoke — SMOKE_BASE_URL. Оба скрипта обращаются к API без логина и пароля.

Экраны каталога, публичной карточки, кабинетов бизнеса и команды подключены к `src/lib/collaboration-gateway.ts` и общим правилам `src/lib/task-service.ts`. Локальный режим использует то же поведение без серверных ключей; API-режим работает через обработчики и Supabase.
