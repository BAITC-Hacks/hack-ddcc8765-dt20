# Демонстрация полного MVP за 5 минут

## Ваша зона ответственности

Показать весь путь: описание бизнеса → уточнения → подтверждённая карточка → рейтинг → публикация → студенческий отклик → ручной выбор → результат этапа → XP. Перед защитой откройте `/catalog` и один раз нажмите «Добавить демопримеры». Подготовьте второй экран `/business`; используйте один origin и один профиль браузера для локального режима.

## Пример для защиты

Все сведения ниже синтетические; их вводит демонстратор.

1. Нажать пример «Заказы пекарни» и «Уточнить задачу».
2. Ответить, что пользователи — два администратора; результат — веб-прототип структурирования заказов; потребность — убрать повторный ввод. Остальные ответы пока пропустить.
3. Нажать «Собрать карточку»: предварительный рейтинг — 45.
4. Назвать задачу «Упростить обработку заказов пекарни».
5. Добавить доступные данные: «20 синтетических заказов в CSV» (+10) и способ передачи файла (+10).
6. Добавить показатель «Доля корректно обработанных заказов» (+10) и условие «Не менее 18 из 20, каждый менее чем за минуту» (+5).
7. Срок «7 дней» (+5), ограничение «Без реальных платежей» (+5).
8. Контакт `demo@example.com` (+5), «Два созвона в неделю» (+3), «Ответ на вопросы в течение рабочего дня» (+2). Получится 100.
9. Открыть предпросмотр. Показать, что сведения можно редактировать.
10. Отметить достоверность, подтвердить карточку, опубликовать.
11. Удалить условие приёмки. Предварительно будет 95, но в опубликованной версии ещё 100. Подтвердить правки и показать обновление.

Отдельная проверка слабой задачи: заполнить только название и минимальные сведения, подтвердить и опубликовать. Низкая оценка не блокирует действие.

## Что честно проговорить

Если `NEXT_PUBLIC_DATA_MODE=local`, AI не вызывается, а каталог, задачи, отклики и XP сохраняются в этом браузере. Между компьютерами данные не синхронизируются. В API-режиме этот же интерфейс работает с Supabase; настоящий AI требует серверных ключа и модели. Шаблонная AI-функция допустима по ТЗ: промпт и формат описаны в `src/lib/server/model.ts`, проверка некорректного ответа и fallback — в `src/lib/server/ai.ts` и тестах. Все контакты и ссылки example.com в примерах синтетические.

## Сквозной показ

| Время     | Что показать                                                                                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:45 | «Создать задачу»: короткое описание пекарни, не менее трёх вопросов, перенос ответов в редактируемую карточку.                                                                      |
| 0:45–2:00 | Заполнить карточку, показать расшифровку и рост рейтинга. Подтвердить сведения и опубликовать.                                                                                      |
| 2:00–2:40 | Нажать «Открыть в каталоге», затем «Все задачи». Найти задачу поиском, показать фильтр готовности и опубликованную карточку ниже 40 баллов.                                         |
| 2:40–3:20 | В карточке выбрать демокоманду, ввести идею, план и срок, отправить предложение.                                                                                                    |
| 3:20–4:00 | В «Кабинете бизнеса» открыть отклики задачи и нажать «Выбрать команду». На примере пекарни показать два отклика: выбор одного не блокирует второй, можно отклонить оба.             |
| 4:00–5:00 | В «Кабинете команды» отправить описание результата. Вернуться в бизнес, проверить его, отметить подтверждение и начислить +10 XP. Обновить страницу: результат и баллы сохраняются. |

Чтобы показать именно **35 → 80 → 100**, сначала заполните только название, контекст, потребность и ожидаемый результат (35). Добавьте данные и источник (+20), показатель и условие приёмки (+15), срок и ограничения (+10): получится 80. Добавьте пользователей (+10), контакт (+5), консультации (+3), обратную связь (+2): 100. Подтверждайте каждую версию, если показываете изменение официального рейтинга в каталоге.

## Проверки каталога и сотрудничества

- Низкий рейтинг не блокирует публикацию или отклик; неопубликованные черновики в каталоге отсутствуют.
- В каталоге только подтверждённое содержимое; неподтверждённые правки редактора не утекают в публичную карточку.
- Фильтры сбрасываются, пустой результат объяснён, загрузка и ошибка имеют отдельные состояния.
- Отклики не ограничены по числу; бизнес может принять несколько или отклонить все.
- Невыбранная команда не может отправить результат, непредъявленный результат нельзя подтвердить.
- Повторное подтверждение не добавляет XP; после подтверждения результат и решение заблокированы.
- После перезагрузки сохраняются задачи, отклики, решения и XP.
- Повторное добавление демопримеров сохраняет внесённые правки.
- Автоматические проверки: `npm test`, `npm run typecheck`, `npm run build`. HTTP-тесты проходят реальные обработчики с тестовым репозиторием; это не проверка подключения к живой базе.

## Проверка перед передачей команде

- `npm ci`, `npm run typecheck`, `npm test`, `npm run build` проходят.
- Сохранённую задачу можно открыть после обновления страницы и через «Мои задачи».
- При возврате на предыдущий шаг введённый текст остаётся.
- Неподтверждённые правки не меняют опубликованную версию.
- Ни один UI-компонент не содержит секретных ключей.
- Участник №2 получил `docs/INTEGRATION.md`, участник №3 знает, что каталог читает только подтверждённую версию.
